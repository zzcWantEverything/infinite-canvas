## 画布「选择参考节点」提示重做

**问题**：视频节点点「+」进入选参考状态后，提示按钮跑到了画布原点附近（左上角），并且被压成竖排小字，距离节点很远、样式差。

**根因**：`InfiniteCanvas` 的 `children` 全部渲染在 `translate(x,y) scale(k)` 的世界坐标层里。这条提示写在 children 内部，用了 `absolute left-1/2 top-4`，于是 `left-1/2` 相对的是塌缩后的世界层宽度，而不是视口；同时容器宽度极小导致文字逐字换行成竖排。

**改法**：
- `web/src/pages/canvas/project.tsx`：把提示从 `<InfiniteCanvas>` 内部移到它外面的兄弟节点（`<section>` 已 `relative`），改视口坐标 `absolute inset-x-0 top-[72px]`（顶栏 `h-16`，下移 8px），`z-[95]`。
- 新样式：圆角胶囊 + `backdrop-blur-md` + 图标（`MousePointerClick`）+ 文字 + 分隔线 + `ESC` 键帽 + 「退出」按钮；`whitespace-nowrap` 防竖排，`animate-in fade-in slide-in-from-top-1 duration-150` 入场。
- `web/src/components/canvas/canvas-node.tsx`：目标节点的「正在添加参考」标签改为同款胶囊，target 态加蓝色脉冲圆点（`selectionBlue` `#2f80ff`），与顶部提示统一视觉语言。
- i18n：`canvas.references.selectingHint` 改为「点击画布节点添加参考」/「Click a canvas node to add a reference」，新增 `canvas.references.exitSelecting`（退出 / Exit）。

**结论沉淀**：画布提示类 UI 不要写在世界坐标层内，否则会被 `translate/scale` 带偏并被压窄；所有跟随视口的状态提示应作为 `InfiniteCanvas` 的兄弟节点渲染。

## 请求层统一 + 错误提示 + 登录态过期

**问题**：错误解析在 `image.ts`、`video.ts`、`audio.ts` 各复制一份；大量 `.catch(() => {})` 静默吞错，用户点完没反应；`refreshUser` 从未被调用，token 过期后仍显示已登录，所有请求失败但无提示。

**新增**：
- `web/src/services/api/http.ts`：`ApiError { kind, status }`、`readApiErrorMessage` / `readStatusError` / `toApiError` / `readAxiosError`、`notifyApiError`（2s 同文案去重）、`reportApiError`、`setApiErrorNotifier`、`setUnauthorizedHandler` / `signalUnauthorized`、`installApiErrorReporting`（unhandledrejection 兜底）。在模块加载时给全局 `axios` 装 response 拦截器，把错误统一收敛为 `ApiError`；**取消请求保持原样**（`axios.isCancel` 提前返回），否则会破坏画布里 `AbortError` 的静默取消语义。
- `web/src/services/api/session.ts`：注册 401 回调 → `clearSession()` + 提示「登录已过期」；`validateSession()` 启动校验一次。**不需要手动跳转**，`AuthGuard` 在 session 变 null 时会带 `from` 跳 `/auth`。
- axios 配置用模块增强加 `requiresAuth?: boolean`，只有 `auth.ts` 的 6 个用户态接口标记，避免把 API Key 请求误判成登录态。

**关键点**：后端没有 refresh token 接口（New API 风格），所以不做静默续期，只做「校验 + 失效重登录」。另外后端会用 `200 + success:false` 表示未登录，`fetchCurrentUser` 里显式 `signalUnauthorized()` 兜住这种情况。

**踩坑**：对 `auth.ts` 跑 `prettier --write` 把整个文件重排了（该文件本来就不符合 prettier），已 `git checkout` 还原后重新只做语义修改。教训：改前先确认目标文件在 HEAD 是否 prettier-clean，不 clean 就不要整体 `--write`。

**遗留**：`npx tsc --noEmit` 有 2 个历史类型错误（`components/layout/model-script-editor.tsx:58`、`stores/use-user-store.ts:37`），与本次改动无关，未修。

## SHA-256 非安全上下文兜底

**现象**：视频节点用 qr-v* 模型 + 连参考图/视频，节点报 `Cannot read properties of undefined (reading 'digest')`。

**根因**：`services/api/video.ts` 的 `qoraUploadAsset` 用 `crypto.subtle.digest` 算参考素材哈希，但 `crypto.subtle` 只在安全上下文暴露；用户用 `http://119.45.0.224/...`（公网 IP + 明文 HTTP）访问，所以它是 undefined。**与后端无关**，请求根本没发出。注意：公网 IP 不等于安全上下文，localhost / HTTPS 才是。

**修复**：
- 新增 `web/src/lib/hash.ts` 的 `sha256Hex()`：有 `crypto.subtle` 就用原生，否则回退 `@noble/hashes` 的 `sha256`（`@noble/hashes/sha2.js`）。
- `video.ts` 改用 `sha256Hex(await blob.arrayBuffer())`。
- 依赖 `@noble/hashes@^2.4.0`；本机无 bun，用 `npm install @noble/hashes --legacy-peer-deps` 安装（pro-components beta 的 peer 冲突是既有的）。`bun.lock` 未同步，需用户跑一次 `bun install`。

**待办**：域名就绪后给部署加 HTTPS，能一并修好 `navigator.clipboard`（粘贴图片/复制）等同类限制。

## qora 参考素材上传报 ERR_CONNECTION_REFUSED（线上排查结论）

现象：画布视频节点带参考素材生成时，`POST http://119.45.0.224:3000/api/qora-assets` 报 `net::ERR_CONNECTION_REFUSED`。

排查（实测）：
- 3000 → 连接失败；80（画柚静态站 + nginx）→ 200；8080（new-api）→ 200。
- `http://119.45.0.224/api/qora-assets` 与 `http://119.45.0.224:8080/api/qora-assets` 都返回 404 `{"message":"no enabled Qora channel found","success":false}`；用错误 key 返回 401 Invalid token。

结论：两层问题。① Base URL 是浏览器本地配置（`use-config-store.ts` 的 `OPENAI_BASE_URL` 默认是 `http://119.45.0.224`，代码里没有 3000；3000 是项目 Docker 部署里 nginx 容器的端口，线上并没有跑），填了 3000 所以直接连不上。② 即使改成 80/8080，new-api 侧仍缺**启用的 Qora 类型渠道**，`/api/qora-assets` 拿不到 Qora key，带参考素材的生成必然失败。`/v1/models` 只返回 10 个 qr-v 模型，承载它们的渠道类型不是 Qora。

## baseUrl 默认同源 + 启动自愈

**背景**：线上把渠道 Base URL 填成 `http://119.45.0.224:3000`（项目 docker 里前端容器的端口），线上并没有这个服务，直接 `ERR_CONNECTION_REFUSED`。

**改动**
- `use-config-store.ts`：`OPENAI_BASE_URL` 从写死 IP 改为 `siteOrigin()`（`window.location.origin`），新建渠道的默认地址也随之跟随站点。
- 新增 `normalizeBaseUrl()`，在 persist `merge` 里对顶层 `config.baseUrl` 和每个 `channel.baseUrl` 各跑一次：
  1. 同 hostname 但 origin 不同（`http://x:3000` vs `http://x`）→ 改成当前 origin
  2. hostname 是 `localhost`/`127.0.0.1`/`[::1]` 且与站点不同 → 改成当前 origin
  3. 站点是 https 且地址是 `http://IPv4` → 改成当前 origin（避免混合内容）
  指向外部域名的地址一律不动（Gemini 官方、OpenAI、第三方中转必须跨域）。
- `vite.config.ts`：dev proxy `/api` 的默认 target 从 `:3000` 改成站点端口，并补 `/v1` 转发，让「同源」在 dev 下真的能用。

**校验**：12 条用例用等价 JS 跑过（同机错端口、localhost、外部 API、dev 同源、dev 连远程、空值等）；`tsc --noEmit` 仍只有 2 个历史错误；`npm run build` 通过。

**未做**：没有按「不同源就一律改 origin」实现——那样会把 Gemini 官方地址和第三方中转全部改坏。也未把默认值改成空串，因为 `isAiConfigReady` 以 `baseUrl.trim()` 判空，空串会让配置引导失效。

**环境坑**：`npm run dev` 在这台机器上起不来，vite 想清 `node_modules/.vite/deps` 时被 safe-delete 守卫拦下（`SAFE_DELETE_BULK_CONFIRM_REQUIRED`，108 个文件 > 阈值 50），不是代码问题。
