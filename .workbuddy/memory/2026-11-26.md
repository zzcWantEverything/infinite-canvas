## 复刻视频（/copy）对齐即刻：分析、分镜、生图这一天的结论

- 参考产品是 `https://jikeai.cc/copy`（登录走 `POST /api/user/login-password`，短信接口登不进去；业务接口还要求浏览器 UA/Origin，否则 `BUSINESS_SOURCE_DENIED`）。拉了「老头」「老汉」两个已分析项目做对照，数据结构见当日结论：
  - `analysis_result` 里 `time_slices / prompt / video_prompt / duration / roles|scenes|items` 是**按生成单元**切的，85 秒的片子只有 9 条，每条 5~15 秒，正文是 `【0-10秒】` + `0-4秒：在 @场景 中…` 的节拍时间线。
  - 我们原来是按硬切切分镜，85 秒会出 30+ 条 1~3 秒的碎片，每段都要单独调一次视频接口。
- 结论：**分镜 = 一次视频生成任务出片的单位**，内部写节拍。已按这个模型重写分析。

## 两段式分析（本日落地）

1. 抽帧上限 32 → 60（1 秒 1 帧 + 切点首帧），长片按比例抽稀。
2. `analyzeOverview`：抽稀 24 帧的全片宫格 + 完整转写 → 资产表（角色带 `voice` 声线）+ 分镜大纲 + 全片 style。
3. `analyzeShotsWindow`：按**时长**切窗（12 秒一窗，窗内抽稀到 16 格），每窗带已锁定资产、本窗切点、本窗台词、`previousEndState`、`previousDialogue`。
4. `clampWindowShots`：窗内相对时间自动加窗起点、越界钳制、单元时长封顶 15 秒。

## 台词时间戳（踩了三轮才对）

- 腾讯 `ResTextFormat=1` 的真实返回长这样：`[0:0.000,0:30.080]  整段台词…`
  - 秒位只有一位（`0:0.000`），原来的 `\d{2}` 正则不匹配 → `transcriptSegments` 恒为 0
  - **整段 30 秒只返回一句**，即使解析出来也没法按窗分配
- 现在的处理：时间码放宽到 1~2 位；`splitBySentence` 按标点拆句、按字数比例分摊时间；完全没有时间戳时 `spreadTranscript` 按句均分到全片；`transcriptForWindow` **按句首时间唯一归属**；`dropRepeatedDialogue` 兜底清空重复 dialogue。
- 台词不带说话人，靠模型按唇形判断；不确定时它写「台词待核对」，这个行为是对的，不要改成硬猜。
- 诊断字段写在历史记录 `source` 里：`transcriptChars / transcriptSegments / transcriptHead / transcriptError`。下次「台词全是待核对」先看这四个值。

## 踩坑

- **Python `re.sub` 的替换串会把 `\n` 当换行**：用它替换 `.join("\n")` 会把源码写成带真实换行的字符串，语法直接报错（Unterminated string literal）。要写反斜杠必须用 `lambda` 或 `chr(92)`。
- **`python - <<'PY'` 里的多行 replace 轻易静默失败**：字符串和文件里差一个字符就 0 命中，assert 之前先 grep 确认，或者改成按行定位替换。
- 编辑前先用 `grep -n` 定位再加行号替换，比整段 triple-quote 匹配稳。
