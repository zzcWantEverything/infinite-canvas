## 本地开发连线上后端（踩坑，重要）

dev 的 vite proxy 原来指向 `http://119.45.0.224`（80 端口），那个端口被 nginx **301 跳转到 https 站点**，
登录 POST 被重定向后 `new_api_refresh` cookie 落在错误域名，后续请求全被判定 token 无效。
修法（已进 `web/vite.config.ts`）：默认 target 改 `https://admin.huayou.cloud`，并在 proxyReq 里把
Origin/Referer 改写成该域名——new-api 的 `/api/user/auth/refresh` 有 `SessionCookieOriginGuard`，
会拿 Origin 和请求 Host 比对，`localhost:3000` 会被 403（`AUTH_ORIGIN_FORBIDDEN`）。
不要在本地设 `VITE_API_BASE`：设了 auth 页会拼绝对地址直连，跨域 + cookie 反而更难搞。

## 发布：图片模型列表 + 余额明细（20261116-185005）

提交 `93f8d6a`。上一版 `20261116-161357`（`./rollback.sh web`），产物 `assets/index-uORuYJ2z.js`。

- **图片模型只有一个**的真正原因：`selectableModelsByCapability` 只读本地 `config.channels[].models`，
  默认配置 image 只有 `gpt-image-2`；视频才有 `/api/user/models` 兜底。已改成图片/视频统一走服务器列表
  （视频按内置能力表过滤，其余按目录 `modality.output` → 关键词），本地配置仅兜底。
- **图片价格算不出来**：线上表达式是 `tier("standard", p * 5 + cr * 1.25 + img * 8 + ...)`，
  裸标识符 `p/cr/img` 在 `lib/billing-expression` 里无法求值（只认 `u("字段")` + `context.usage`），
  而且一次生成的真实 token 用量前端不可能知道。目录 `pricing.examples` 也救不了。
  → 下拉里改成标「按用量计费」，等后端配 `model_price` 或静态 `tier(...,fixed(x))` 才有真价。
- **单位事件（我判断错了一次）**：曾以为 runtime 的 `cost` 是微元，在 `lib/model-price.ts` 加了 `/1e6`。
  实际线上 27 个表达式全是 `tier("base", 3.82)` / `tier("base", u("seconds") * 0.65)`，**返回值就是元**；
  只有 `fixed(n)` 在 runtime 内部会 `*1e6`，而线上没有任何模型用 `fixed`。结果所有模型价格变成 ¥0，
  11-17 已回退（`60469ac`），验证 `vw_80a876c3@309` → 约 ¥8.98/次、`vw_0cf8f13e@259` → 约 ¥0.98/秒。
  **教训：不要拿一个自造的 `fixed(5.5)` 样本反推线上单位，先看真实 `billing_expr` 分布。**
