## 图片生成任务化（一天内反复返工，结论记在这里）

- 目标：图片也像视频那样，刷新后能按 task id 续查。上游 miniKey 的 `/openapi/v1/images` 本来就是**异步任务**（`task_id` + `GET /images/{id}` 轮询），网关也早已把图片落成持久任务（`platform=minikey`、`action=text_to_image`）。
- 网关侧**不需要改插件**：通用任务接口 `POST /v1/tasks/minikey`（body 带 `model/prompt/size/images`）即可提交，`GET /api/task/self?task_id=` 查状态、`GET /api/task/{id}/artifacts` 取图。
  **注意认证**：`/v1/tasks/{id}` 走 TokenAuth，页面里没有 sk- 令牌会一直 401；要用会话认证的 `/api/task/*`。
- 参考图必须内联成 **Base64 Data URL** 放进 `params.images`（插件里由 `req.images` 转过去）。给 `params.images` 传假图（只有 PNG 文件头）上游会判「参考图不是有效图片文件」——不要用假图做验证。
- 上游 `banana` 渠道分组会「临时下线」，此时任何参数都失败，报错文案是「渠道分组均无法处理本次请求：banana（临时下线）」，与代码无关。

## 踩过的三个坑（都在「task id 存哪儿」上）

1. 只改 `project.tsx` 的配置节点分支 → 图片节点入口没覆盖，仍走同步 `requestEdit`
2. 观察者写「当前 loading 的节点」→ 写到了源节点（源节点也在 loading）
3. 项目级 localforage 队列 → 回填时找不到匹配节点（刷新后已被标成「已中断」）

最终照抄视频那套：`imageTaskId` 写进节点元数据 + `forceCloudPushRef` 立刻落盘 + 10 秒兜底扫描续查。

## 构建陷阱（浪费了很多轮）

- 源码改了但 `npm run build` 产物 hash 不变 → 说明改动**没有落进 bundle**。验证方法：在 `dist/assets/index-*.js` 里 grep 新增的字符串（如 `api/task`），没有就是没编进去。
- 别只看「✓ built」，也别只比 hash —— 直接查字符串最快。

- 视频任务去掉 90 分钟转后台，改为「只要上游没判失败就继续轮询」，配合 10 秒兜底扫描。
