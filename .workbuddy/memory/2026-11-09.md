# 2026-11-09

## GitHub 推送失败（Recv failure: Connection was reset）

**现象**：`git pull --tags origin main` 报 `fatal: unable to access ... Recv failure: Connection was reset`。

**诊断**：
- 系统代理开关是**关闭**的（`HKCU:\...\Internet Settings` 的 `ProxyEnable = 0`），但 `ProxyServer` 里存着 `127.0.0.1:7897`（Clash Verge 端口），7897 端口本身在监听。
- 本机直连 `https://github.com` 超时（curl 返回 `000`，10s）。
- 走 `http://127.0.0.1:7897` 访问 GitHub 正常（200，0.95s），`git ls-remote` 也能拉到远端 refs。

**结论**：纯网络问题——代理软件在跑，但系统代理没开，git 走直连被重置。

**处理**：
- 只对 GitHub 生效的 scoped 配置（比全局 `http.proxy` 更安全，不影响 Gitee 等）：
  ```
  git config --global http.https://github.com.proxy http://127.0.0.1:7897
  ```
- 推送成功：`fb3bdaa..f61b1ec  main -> main`，同时新建 `v0.20.0`、`v0.20.1` 两个 tag。
- 推送时有一条无害告警：`git-credential-manager.exe: No such file or directory`，是 PortableGit 版本目录变化导致，凭据本身可用，不影响推送。

**以后**：换代理软件或端口时要同步改这个配置；或者直接在 Clash 里开「系统代理 / TUN 模式」，git 就会自动跟随，不用单独配。
