- `lib/model-picker-groups.ts` 新增 `MODEL_GROUP_OVERRIDES`（按模型 id 指定分组），
  灵境 8 个档位全部归到「特惠优选」，条目名去掉重复的「特惠版」前缀。
- 只做展示分组，取值仍是 `渠道::模型名`，路由/计费不变；不用前缀匹配是因为老 miniKey 渠道也有「特惠版 Seedance」，
  会被误吸进来。

## 图片生成：参数与比例全面对齐

- 后端只有 `tt-image-2` 收 `size`，其余图片模型只认 `aspectRatio + imageSize`；之前一律发 `size`
  导致「选 16:9 出方图」。前端这边配合改成**按目录能力渲染比例**：
  图片面板从 `catalogVariant(model).capabilities.fields.ratio.enum` 取可选比例，没有声明才退回香蕉系写死列表。
- 图片面板的「分辨率」只给 `1k / auto`（上游目前只开放 1K 档），常量 `AVAILABLE_IMAGE_SCALES`。
- 图片默认比例从 `1:1` 改成 **16:9**；`persist` 加 `version: 1` + `migrate`，只把仍是旧默认值 `1:1` 的配置升上来，
  用户自己选过的比例不动。
- 同理，1k 预设里 2:3 / 3:2 / 21:9 / 9:21 压到 150 万像素内（`960x1440`、`1440x960`、`1680x720`、`720x1680`），
  否则界面写 1k、上游按 2K 计费。

## 分档价差大的模型：选中即落默认档

- 特惠按秒款（`model-380066518676792496`）480P 0.18/秒、720P 0.315/秒，差 75%。
- 做法：`videoModelDefaultResolution(model)` 指定默认档，**选中模型时**由 `applyNodeConfigPatch` /
  store 的 `updateConfig("videoModel")` 把 `vquality` 与 `size` 一起落档；下拉报价固定按这一档报，
  和面板实价一致。
- 教训：只在面板 effect 里落档不够——旧节点已经有 `vquality=720` 时，不重新选模型就不会触发。

## 提示词引用参考图编号：发送前本地校验

- 上游（miniKey）会校验「提示词里的图片编号 ≤ 实际收到素材数」，越界直接 502 并附一段 curl 教程。
- 新增 `lib/image-reference-prompt.ts` 的 `maxImageReferenceIndex()`：识别 `图片N` / `图N` / `Image N`，
  超过 100 的当噪声忽略；`createVideoGenerationTask` 在派发前比对 `min(附件数, 模型 maxImages)`，
  超界直接抛「提示词引用了第 N 张参考图，但只连接了 M 张」。

## 错误文案：改成白名单式收敛

- `lib/upstream-error.ts` 重写：先挡 HTML / 图片编号 / **价格**（货币符号+数字、`元`/`积分`、倍率、单价、
  price/billing/credit），再按「审核 / 超时 / 繁忙 / 参数不支持 / 上游内部标记 / 超长」归类，
  其余（我们自己后端的短文案，如「用户额度不足」）原样透出。
- `http.ts` 新增 `readFailureMessage()`：任务失败原因（200 响应里的 error 文案）也必须过一遍脱敏，
  `video.ts` 里 12 处 `readApiErrorMessage(...) || 兜底` 全部换成它。
- 新增 i18n key：`contentBlocked` / `generationTimeout` / `lineBusy` / `upstreamParamInvalid` /
  `promptImageReferenceOutOfRange` / `imageReferenceMismatch`。
